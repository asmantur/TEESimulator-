# TEESimulator 简体中文版

本分支将模块 WebUI 的导航、配置说明、操作按钮、状态、校验提示和确认对话框翻译为简体中文。密钥证明、路由和注入逻辑沿用原项目。

以易懂、准确为主，不强求全中文。`Keybox`、`Attestation`、`TrustedEnvironment`、`StrongBox` 及密钥类型 `Generated`、`Delegated`、`Patched`、`Untouched` 等术语可保留英文；需要说明时使用中文解释，不改变其上游含义。

## 功能入口

| 页面 | 用途 |
| --- | --- |
| 配置方案 | 为应用分配密钥箱、运行模式、安全补丁、系统版本和设备标识。每个应用条目只能属于一个方案。 |
| 密钥箱 | 导入、重命名、删除 XML 密钥箱，查看证书链、有效期和吊销检查结果。也可查看设备提供的远程密钥配置（RKP）选项。 |
| 密钥 | 查看目标应用的密钥及处理方式，按应用、用途或类型筛选。删除操作会让应用在下次使用时重新创建密钥。 |
| 系统 | 查看守护进程、拦截器、设备信息采集结果、替代值和模块更新状态。 |
| 日志 | 查看运行日志，按级别、标签和内容筛选，暂停显示或导出报告。 |

## 常用设置

- **修补模式（patch）**：保留硬件密钥，仅使用密钥箱重新签署密钥证明；需要相应硬件安全级别可用。
- **生成模式（generation）**：使用软件生成密钥。相应硬件不可用时，模块会回退到此模式。
- **作用范围**：选择应用。主用户的应用条目为 `com.example.app`，其他用户为 `com.example.app@10`。应用名称、包名和用户自定义名称按设备原样显示。
- **自动纳入新应用**：以守护进程建立的应用基准为界，纳入之后安装的新应用；重新扫描时发现，不会实时监听安装。仅允许一个方案启用。下拉配置方案页面可重新扫描。
- **补丁快捷选项**：“系统属性”写入 `system_property`；“当前月份”写入 `today`；“不提供”写入 `no`；“每月 5 日”写入 `YYYY-MM-05`，当本月 5 日尚未到来时按上月处理。留空使用设备采集值。
- **设备标识**：留空使用设备采集值；非空时覆盖当前方案中的对应标识。
- **原始采集值 / 替代与合成值**：前者是设备实际报告的信息；后者是模块提供的替代、补充或合成信息，不能视为真实硬件状态。

方案名称仍须为 1–32 个英文字母、数字、`-` 或 `_`，例如 `default`。密钥箱文件名仍须符合原项目规则并以 `.xml` 结尾。显示中文不会改变配置文件键名、协议值、文件路径、包名或命令。

## 使用与构建

运行要求、密钥箱格式和模块安装方法见 [原项目说明](README.md)。需要 Android 10+、64 位设备及 Magisk、KernelSU 或 APatch。模块不附带私有密钥箱。

```sh
# 先准备 README 和 CI 指定的 SDK、NDK、Java 21、Rust 与子模块。
./gradlew zipRelease
# 输出：out/TEESimulator-…-Release.zip
```

WebUI 文件会随原有打包任务一起进入模块，无需独立的语言包或联网翻译服务。请刷入包含这些改动的完整模块 ZIP。仅将 `module/` 目录压缩不能替代完整构建，它不包含生成的 dex 和原生二进制。

“系统”页和模块管理器的更新入口均指向此 Fork 的中文版发布。首个自动构建发布完成后，模块管理器即可读取更新描述。远端发布说明、守护进程返回的原始错误、日志、证书内容和用户数据保留原文，便于诊断。

自动更新目前已按用户要求暂停，只保留 GitHub Actions 手动运行入口，不会定时或因推送而自动合并、构建、发布。恢复后可沿用[自动维护方案](docs/zh-CN-maintenance.md)。

开发验证：

```sh
node --test module/webroot/tests/domain.test.mjs
./gradlew :app:checkWebrootJs
```
